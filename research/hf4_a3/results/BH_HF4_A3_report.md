# BH-HF4-A3 — доступность геометрии горизонта

Дата: 16 сентября 2026 года. Проект «Пространства».

**Аудит присланных файлов завершён. Найден обоснованный способ проверить восстановление геометрии из существующих контрольных точек QC0. Для завершения A3 нужен один небольшой пакет с компьютера пользователя.** Сами контрольные точки в этой среде отсутствуют; их фактическое содержимое ещё не проверено.

Подтверждённые этапы HF3, Yitian A1–A4 и HF4-A1/A2 не пересчитывались. Сохраняется состояние QC0: эволюция завершена при `t=105M`, `it=53760`, код завершения 0. Результаты двух разных симуляций — QC0 и SpEC/Yitian — остаются раздельными.

## 1. Что обнаружено в доступных файлах

| Набор | Подтверждённое содержимое | Чего это пока не даёт |
|---|---|---|
| Yitian, `Moments_500M_L30.h5` | Два комплексных массива 5001×81 и время 0–500M | Нет площади A(t), координат поверхности, поточечной метрики и карты переноса авторских углов |
| QC0, `BH_HF3_R7A_output.zip` | 647 файлов: волновые ряды, диагностика горизонтов, параметры и журналы | В архиве нет полных поверхностных HDF5/VTK или файлов формы `h.t…ah….gp` |
| QC0, `sf_radius..asc` | 161 строка на 95–105M, по одному отсчёту сетки для каждой из шести поверхностей | Это не двумерная сетка формы |
| QC0, статистические файлы `qlm_twometric` | Средние, нормы, минимумы и максимумы | Эти свёртки не задают метрику в каждой точке |
| QC0, контрольные точки на компьютере пользователя | Их существование подтверждалось предыдущими этапами; здесь их нет | Нельзя объявить конкретные поверхностные массивы найденными до чтения файлов |

У `sf_radius..asc` заголовок указывает колонки индексов 6–8. Во всех строках они равны `(0,0,0)`. Координатные служебные колонки 10–12 также нулевые. Это описание единственного выводимого отсчёта массива, а не утверждение, что поверхность находится в начале координат. Остальные файлы `sf_radius` содержат статистические свёртки и не интерпретировались как координатные таблицы.

В параметрах последнего запуска установлены `IOHDF5::out_every=0`, пустой список обычного HDF5-вывода, `AHFinderDirect::output_h_every=0`, а также отключены обычные 1D/2D ASCII-выводы. Сохранение checkpoint при завершении включено. Поэтому отсутствие отдельного фильма поверхностей ожидаемо, но не доказывает потери всех геометрических данных. Значение `output_h_every=0` действительно отключает запись формы в AHFinderDirect. [Документация AHFinderDirect](https://einsteintoolkit.org/thornguide/EinsteinAnalysis/AHFinderDirect/documentation.html).

## 2. Найденный путь через контрольные точки

Документация SphericalSurface прямо предусматривает автоматическое сохранение и восстановление поверхностных массивов. Для интерпретации радиусов нужны начало координат, угловые шаги, размеры сетки, фиктивные граничные точки и признаки валидности. [Документация SphericalSurface](https://einsteintoolkit.org/thornguide/CactusNumerical/SphericalSurface/documentation.html).

Открытый код EinsteinAnalysis проверен на ревизии `edd7fe658cb6748cd9ac8efcea314214b87bc043`. Это ещё не проверка установленной у пользователя сборки; поэтому сборщик также берёт соответствующие небольшие локальные файлы исходного кода.

| Группа данных | Что установлено по открытому коду | Что требуется проверить в QC0 |
|---|---|---|
| Форма AHFinderDirect | Объявлены массив радиусов, центры и флаги для сохранения/восстановления | Наличие, время и соответствие нужному горизонту |
| Форма и координаты QLM | Память выделяется; запрета checkpoint для этих групп нет | Полнота сетки и актуальность данных |
| Комплексный касательный вектор QLM | Его компоненты сохраняются в отдельной группе без запрета checkpoint | Комплексный формат, нормировка, валидность и время |
| Поточечная двумерная метрика QLM | В интерфейсе явно стоит `Checkpoint="no"` | Её прямое наличие не предполагается |
| Эволюционные объёмные поля | Их описание может быть в checkpoint | Сборщик читает только метаданные этих полей |

Основания: [интерфейс QLM](https://bitbucket.org/einsteintoolkit/einsteinanalysis/src/edd7fe658cb6748cd9ac8efcea314214b87bc043/QuasiLocalMeasures/interface.ccl), [расписание QLM](https://bitbucket.org/einsteintoolkit/einsteinanalysis/src/edd7fe658cb6748cd9ac8efcea314214b87bc043/QuasiLocalMeasures/schedule.ccl), [интерфейс AHFinderDirect](https://bitbucket.org/einsteintoolkit/einsteinanalysis/src/edd7fe658cb6748cd9ac8efcea314214b87bc043/AHFinderDirect/interface.ccl).

Главное уточнение маршрута: отсутствие сохранённой группы двумерной метрики ещё не означает, что её необходимо заново вычислять эволюцией. Сохранённая нормированная касательная тетрада может содержать нужную информацию.

## 3. Почему касательные векторы могут восстановить метрику

Это условный математический способ, а не уже выполненная реконструкция QC0.

Пусть `X^i(θ,φ)` — сохранённые координаты поверхности, а `E^i_A=∂_A X^i` — два касательных направления. В QLM комплексный вектор строится как

\[
m^i=(u^i+i v^i)/\sqrt2,
\]

где `u,v` — касательные векторы, ортонормированные с физической пространственной метрикой. Временная компонента у этого вектора должна быть нулевой с точностью представления. Это следует из проверенного алгоритма [построения тетрады](https://bitbucket.org/einsteintoolkit/einsteinanalysis/src/edd7fe658cb6748cd9ac8efcea314214b87bc043/QuasiLocalMeasures/src/qlm_tetrad1.F90).

Решив `E^i_A m^A=m^i`, получаем обратную метрику поверхности:

\[
q^{AB}=2\operatorname{Re}(m^A\overline{m^B}),\qquad q_{AB}=(q^{AB})^{-1}.
\]

Такое тождество также отмечено в исходном коде [вычисления двумерной метрики](https://bitbucket.org/einsteintoolkit/einsteinanalysis/src/edd7fe658cb6748cd9ac8efcea314214b87bc043/QuasiLocalMeasures/src/qlm_twometric.F90). Использование обычного линейного решателя здесь лишь находит коэффициенты в касательном базисе; оно не заменяет физическую пространственную метрику евклидовой.

Независимая алгебраическая проверка на 400 синтетических положительно определённых метриках дала максимальную относительную ошибку `7.47×10⁻¹⁴`. Фазовое вращение комплексного вектора сохраняет результат с ошибкой не более `5.61×10⁻¹⁴`. Эти числа проверяют формулу и её реализацию. Они **не являются оценкой ошибки симуляции** и не проверяют численное дифференцирование реальной сетки.

Перед применением к данным обязательны: одинаковое время координат и тетрады, правильный индекс поверхности, актуальные флаги QLM, совпадение MPI-копий, учёт порядка индексов и граничных точек. Затем проверяются касательность, невырожденность метрики и интеграл площади по отношению к сохранённой площади QLM. Последняя сверка проверяет согласованность реконструкции внутри одного расчёта, а не независимую численную сходимость.

## 4. Что доступно для ветки SpEC

Уже полученный архив Yitian не содержит недостающих геометрических массивов. В общей документации SXS различаются два потенциально полезных продукта:

- `Horizons.h5`: время, центры, неприводимая масса и спин. Из неприводимой массы можно получить площадь `A=16π M_irr²`.
- `HorizonsDump.h5`: для некоторых симуляций содержит координаты поверхности и распределения геометрических скаляров.

Документация не гарантирует наличие второго файла именно для нужной реализации SXS:BBH:0389. Конкретный совпадающий файл в этом этапе не получен. Также ещё не установлены соответствие разрешений, точное преобразование времени и связь каталоговых углов с переносимыми углами Yitian. Поэтому каталоговые значения не подставлялись в его ряды. [Документация файлов SXS](https://data.black-holes.org/waveforms/documentation.html).

Для совмещения карт A2 с реальной поверхностью SpEC нужны данные той же реализации: площадь, сетка поверхности с физической метрикой или сама двумерная метрика, а также отображение авторских углов на сетку. Координаты и скаляры из `HorizonsDump.h5` сами по себе не гарантируют полной внутренней метрики. Для изображения двух отдельных горизонтов до появления общего нужны также ранние поверхности AhA/AhB. Никаких писем авторам не отправлено.

## 5. Подготовленная программа сбора

Файл `BH_HF4_A3_collect.py` выполняет ограниченный обход каталогов `qc0*` в `~/simulations`, читает HDF5 в режиме `r` и формирует отдельный ZIP. В пакет входят:

- описания checkpoint: пути, размеры, итерации из имён, части MPI, наборы данных и доступные атрибуты;
- небольшие массивы форм, координат, тетрады, времени и флагов, если они действительно найдены;
- относящиеся к QC0 параметры, ограниченная диагностика и выбранные исходные файлы используемых модулей.

Итерация из имени не объявляется измеренным временем. Большие трёхмерные массивы не считываются; checkpoint целиком не копируются. Максимум одного извлекаемого поверхностного массива — 2 MiB, суммарного несжатого объёма таких массивов — 96 MiB. Превышение лимита отмечается в результате. Программа не запускает Cactus, не меняет параметры и не записывает в исходные файлы. При повторном запуске прежний результат сохраняется, а новый получает временную метку.

Для извлечения массивов нужны `numpy` и `h5py`. Если они отсутствуют, программа всё равно создаёт честно обозначенную инвентаризацию файлов без извлечения HDF5; она не сообщает ложный успех.

Выполнены 14 проверок сборщика: точность копирования чисел, комплексный и составной форматы, неизменность исходных байтов, отсутствие чтения большого объёмного поля, обработка повреждённого файла, внешних HDF5-ссылок и ограничений размера, сохранение предыдущего результата и работа без HDF5-библиотеки. Тесты синтетические; доступа к машине пользователя они не заменяют.

Сохраните программу в «Загрузки» Windows и выполните в Bash:

```bash
source ~/gw_env/bin/activate
python /mnt/c/Users/Admin/Downloads/BH_HF4_A3_collect.py
```

Ожидаемый первый результат:

```text
C:\Users\Admin\BH_HF4_A3_inventory.zip
```

Если файл с таким именем уже существует, фактическое новое имя программа напечатает в конце. Передать нужно только полученный ZIP.

## 6. Следующая контрольная точка

Текущий статус: `BH_HF4_A3_AVAILABLE_DATA_AUDIT_COMPLETE_LOCAL_GEOMETRY_INVENTORY_PENDING`.

После получения ZIP сначала завершаем проверку A3, затем выбираем вариант A4:

| Реально найденные данные | Действие A4 |
|---|---|
| Координаты, валидная тетрада и описание угловой сетки | Проверить восстановление метрики и площади; получить геометрически проверенные снимки в сохранённые моменты |
| Только полные радиусы/координаты | Построить честно обозначенную координатную форму; физическую метрику считать ещё не восстановленной |
| Нет нужных поверхностных массивов, но есть достаточные объёмные поля | Проектировать отдельное чтение существующего снимка с проверкой версии кода и формата, без автоматического назначения новой эволюции |
| Недостаточно ранних временных снимков | Зафиксировать пробел истории; поздний checkpoint не восстанавливает всю раннюю динамику |

Редкие снимки и несколько прошлых временных уровней не образуют плотную историю слияния. Координатное изображение горизонта, его внутренняя метрика и изометрическое вложение в евклидово пространство — разные результаты. Условная метрика по мультиполям или искусственный радиальный рельеф не выдаются за измеренную трёхмерную форму.

Точка A2 и все её численные результаты остаются действующими. Повторный расчёт карт, фильма A2, кольцевания HF3 и мультипольных подгонок Yitian для продолжения не требуется.
